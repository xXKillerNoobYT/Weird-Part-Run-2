### 🎯 Skill: parts-sql-schema-checker

**Why:** `PartsService.swift` at 6,834 lines is too large to audit manually before each change. A skill that diffs the service's SQL against the migration file (by extracting column names from CREATE TABLE statements and checking them against SELECT/INSERT/UPDATE queries) would catch drift automatically. This would have prevented all 64+ historical SQL column bugs.

**Where:** `.claude/skills/parts-sql-schema-checker/SKILL.md`

**Invocation:** Claude-only (run as part of C3 hunt-fix-clean for parts area)

**Implementation outline:**
1. Read `AppDatabase+Migrations.swift` — extract table→column mappings via regex
2. Read `PartsService.swift` — extract all SQL strings via regex
3. Cross-reference: for each SQL query, check every referenced `table.column` exists in the migration map
4. Output: list of mismatches with line numbers

**Decision:** Apply now (add to plan and generate the skill). This is the single highest-ROI automation for the Parts area given the bug history. Recommend implementing in the next iteration when C4 (tests) or C8 (security) check is active.
