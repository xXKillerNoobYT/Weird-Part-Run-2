# iOS Jobs Pages — Design Plan

> **Purpose:** Comprehensive design decisions for all Jobs-related pages in the iOS app. Covers job statuses, job list, per-job dashboard, clock integration, warranty system, continuous jobs, and QR codes.
>
> **Source:** Design conversation 2026-03-23. Implements pages in `Weird Parts IOS/Features/Jobs/`.
>
> **Files:** `JobsListPage`, `IOSJobDetailPage`, `IOSJobDetailTabView`, `IOSCreateJobSheet`, `IOSEditJobSheet`, `IOSClockPage`, `IOSDailyReportsPage`, `IOSQuestionnairePage`, `JobReportsPage`, `LaborPage`

## 1. Job Status Types

Jobs have six distinct statuses. Each status has specific visual treatment and behavioral rules.

| Status | Color | Icon | Who Sees | Notes |
|--------|-------|------|----------|-------|
| **Active** | Green | `hammer.fill` | Everyone | Normal working state |
| **On Hold** | Orange | `pause.circle.fill` | Everyone | Generic hold — could be materials, weather, etc. |
| **Payment Hold** | Red | `dollarsign.circle.fill` | Managers only (workers see "On Hold") | Customer hasn't paid. Workers see generic "On Hold" with no financial details. Managers see red "$" badge. |
| **Completed** | Blue | `checkmark.circle.fill` | Everyone | All work done, final paperwork submitted |
| **Cancelled** | Gray | `xmark.circle.fill` | Everyone | Job cancelled before completion |
| **Warranty** | Purple | `shield.fill` | Everyone | Job in warranty period. Default 1 year, adjustable per job. |
| **Continuous** | Light Gray | `arrow.triangle.2.circlepath` | Everyone | Ongoing jobs (e.g., maintenance contracts). Per-to-do warranty. Never "complete" in the traditional sense. |

### Payment Hold Rules

- **Red banner** at top of job detail: "This job is on payment hold. Workers cannot clock in."
- Workers can VIEW the job but CANNOT clock in
- Resume button requires hat: `manage_payment_holds`
- When a manager puts a job on Payment Hold, workers already clocked in get a notification to clock out
- Payment Hold reason is visible only to users with `view_job_financials` hat

### Status Transitions

```
Active → On Hold → Active (resume)
Active → Payment Hold → Active (resume, hat-gated)
Active → Completed
Active → Cancelled
Completed → Warranty (automatic when warranty period starts)
Warranty → Completed (when warranty period expires)
Active → Continuous (set at creation, cannot change after)
```

## 2. Job List Page (`JobsListPage`)

### Smart Cards (Filter Bar)

Smart cards replace traditional filter chips. Tap a card to filter, tap again to show all. Each card shows a live count.

| Card | Filter | Color | Icon |
|------|--------|-------|------|
| Active | `status = active` | Green | `hammer.fill` |
| On Hold | `status IN (on_hold, payment_hold)` | Orange | `pause.circle.fill` |
| Completed | `status = completed` | Blue | `checkmark.circle.fill` |
| Warranty | `status = warranty` | Purple | `shield.fill` |
| Continuous | `status = continuous` | Gray | `arrow.triangle.2.circlepath` |
| All | No filter | Default | `list.bullet` |

### Job Card Design

Each job in the list renders as a card with:

```
+--------------------------------------------------+
| [Stage Icon] Job Name                    [Status] |
| Customer Name · Job #12345                        |
|                                                   |
| Stage: Rough-In  [===========-------] 65%        |
|                                                   |
| [AI Summary - 1-2 lines, cached 1hr]             |
|                                                   |
| Hours: [====----] 120/200    Budget: [======--] $ |
| (only shown if data exists for that metric)       |
+--------------------------------------------------+
```

**AI Summary on each card:**
- 1-2 line natural language summary of current job state
- Cached for 1 hour per job (stored in memory, not DB)
- Generated by Apple Foundation Models on-device
- Falls back to "No summary available" if AI unavailable
- Example: "Rough-in 65% complete. 3 open to-dos. Crew of 4 today. On schedule."

**Stage Progression Bar:**
- Shows current stage as a progress bar across all defined stages
- Stages are job-type specific (defined in job templates)
- Current stage name shown as text label

**Dual Progress Bars (conditional):**
- **Hours bar:** Only shown if the job has hour estimates. Shows `actual_hours / estimated_hours`.
- **Budget bar:** Only shown if the job has budget data AND user has `view_job_financials` hat. Shows `actual_spend / budget`.
- If neither exists, this row is hidden entirely (no empty bars)

### Swipe Actions

- **Swipe right:** Quick AI summary (regenerates, ignores cache)
- **Swipe left:** Status change (managers only, hat: `manage_job_status`). Shows picker with valid transitions.

### Search & Sort

- Search: job name, customer name, job number, address
- Sort: by name, by date created, by status, by last activity
- Pull-to-refresh updates all cards

## 3. Per-Job Dashboard (`IOSJobDetailPage`)

The job detail page is a full dashboard for a single job, not just a detail view.

### Header

```
+--------------------------------------------------+
| [Back] Job Name                    [Edit] [More]  |
| Customer · Job #12345 · Status Badge              |
| Stage: Rough-In                                   |
+--------------------------------------------------+
```

### Stage Progression

Full-width stage progression bar with stage labels. Tappable to see stage details (what's included, % complete, to-dos in each stage).

### Smart Cards Row

| Card | Content | Hat Required |
|------|---------|--------------|
| Hours | `actual / estimated` with % | None |
| Budget | `spent / budget` with % | `view_job_financials` |
| JPOs | Count of open JPOs | None |
| To-Dos | `completed / total` | None |

Each card is tappable to navigate to the relevant detail tab.

### AI Summary Section

- 3-5 line summary of job state, recent activity, upcoming work
- Cached 1 hour
- "Refresh" button to regenerate
- Shows last-generated timestamp

### Today's Activity

- Who's on site today (from clock data)
- Hours logged today
- To-dos completed today
- Parts used today (from movements)

### Quick Actions (Hat-Gated)

| Action | Hat Required |
|--------|-------------|
| Clock In | Any worker assigned to job |
| Add To-Do | `edit_job_todos` |
| Create JPO | `create_jpo` |
| Add Note | Any assigned worker |
| Change Status | `manage_job_status` |
| View Financials | `view_job_financials` |

### Warranty Info Section

- **Standard jobs:** Shows warranty period (default 1 year), start date (= completion date), end date
- **Adjustable:** Managers can change warranty period per job (hat: `manage_job_warranty`)
- **Continuous jobs:** Shows "Per-to-do warranty" with list of to-dos and their individual warranty periods

### Financial Summary (Hat-Gated)

Visible only to users with `view_job_financials`:

- Total labor cost
- Total parts cost (from FIFO cost layers)
- Total subcontractor cost
- Budget remaining
- Profit margin (if billing data available)

## 4. Continuous Jobs

Continuous jobs are ongoing work (e.g., maintenance contracts, service agreements) that never truly "complete."

### Key Differences from Standard Jobs

| Aspect | Standard Job | Continuous Job |
|--------|-------------|----------------|
| Completion | Has end date, marks complete | Never completes |
| Warranty | Job-level, default 1 year | Per-to-do, configurable |
| Appearance | Full color | Light gray card background |
| Status options | All 6 | Only Active, On Hold, Payment Hold, Cancelled |
| Stage progression | Linear stages | No stages (to-do driven) |
| Worker assignment | Any worker | Only qualified workers (skill-based) |

### Per-To-Do Warranty

- Each to-do in a continuous job has its own warranty period
- When a to-do is marked complete, its warranty clock starts
- Warranty period is configurable per to-do (default: job's warranty setting)
- New to-dos can be classified as:
  - **New Work** — new scope, billable
  - **Warranty Work** — related to a previous to-do, covered under warranty
  - Manager review required for warranty classification (hat: `classify_warranty_work`)

### Visual Treatment

- Light gray card background in job list (not white like standard jobs)
- No stage progression bar (replaced by to-do completion ratio)
- To-do list is the primary organization (not stages)

## 5. Clock Page Integration

The Clock page lives under Dashboard (per previous design decision — clock is a Dashboard feature, not a Jobs feature). But it has deep integration with Jobs.

### Clock-In Flow

1. User taps "Clock In" on Dashboard
2. GPS-sorted job picker shows available jobs (nearest first)
3. **To-Do Picker:** After selecting job, user picks which to-do they're working on
4. **Work Type:** If job is in Warranty status, user selects New Work or Warranty Work
5. Clock starts with live elapsed timer

### During Clock Session

- **Live elapsed timer** showing hours:minutes since clock-in
- **Current to-do** displayed prominently
- **Mark Done + Pick Next:** Complete current to-do and immediately select next one
- **Switch To-Do:** Change to a different to-do without clocking out
- **Switch Job:** One-action job switch — clocks out of current, clocks into new job. Single tap, not clock-out-then-clock-in.

### To-Do Picker Details

- Shows all incomplete to-dos for the selected job
- Grouped by stage (for standard jobs) or by category (for continuous jobs)
- Each to-do shows: name, priority, estimated time (if set)
- "General Work" option for work not tied to a specific to-do

### Work Type Selection (Warranty Jobs)

When clocking into a job with warranty status:

- **New Work:** Fresh scope, will be billed separately
- **Warranty Work:** Covered under existing warranty, reference the original to-do
- This classification flows into billing/reports

## 6. Warranty System

### Default Behavior

- All standard jobs have a default warranty period of **1 year**
- Warranty period starts when job status changes to "Completed"
- After warranty expires, job status changes from "Warranty" to "Completed" (final)
- Default warranty period is a company setting (Settings → Job Defaults)

### Per-Job Adjustments

- Managers can adjust warranty period for individual jobs (hat: `manage_job_warranty`)
- Options: 6 months, 1 year, 2 years, 3 years, 5 years, Custom (enter days)
- Adjustment is logged in job activity history

### Continuous Job Warranty

- No job-level warranty — warranty is per-to-do
- Each to-do gets its own warranty period when marked complete
- Default per-to-do warranty inherits from the job's warranty setting
- Can be overridden per to-do by managers

### Warranty Work Classification

When new work appears on a warranty job:
1. Worker creates a new to-do
2. Worker marks it as "Warranty" or "New Work"
3. **Manager review required** — manager confirms or reclassifies (hat: `classify_warranty_work`)
4. Warranty work: no additional billing
5. New work: creates billable record

## 7. Job QR Codes

- Each job has a printable QR code
- QR encodes: `wiredpart://job/{job_id}`
- Use case: Print and attach to panel schedules, job binders, site signage
- Scanning the QR code opens the job detail page
- Can also be used for quick clock-in: scan QR → confirm → clocked in
- Print via QR Label system (see `docs/plans/qr_plan.md`)

## 8. Create/Edit Job Sheets

### Create Job Sheet (`IOSCreateJobSheet`)

Required fields:
- Job name
- Customer (picker from Customers list)
- Job type (from company-defined types)
- Address

Optional fields:
- Job number (auto-generated if blank)
- Estimated hours
- Budget
- Stages (from template or custom)
- Assigned workers
- Start date
- Warranty period (defaults to company setting)
- Continuous job toggle (cannot be changed after creation)
- Notes

### Edit Job Sheet (`IOSEditJobSheet`)

Same fields as create, except:
- Cannot change: job type, continuous toggle
- Additional fields: status change (hat-gated), warranty adjustment
- Shows creation date and last modified date

## 9. Daily Reports & Labor

### Daily Reports (`IOSDailyReportsPage`)

- System-generated from clock data and to-do completions
- One report per job per day (only days with activity)
- Shows: who worked, hours per person, to-dos completed, parts used, notes
- AI-compiled summary at top (Apple Foundation Models)
- Template-driven layout (Office configures templates)

### Labor Page (`LaborPage`)

- Per-job labor breakdown
- Hours by worker, by date range
- Cost calculations (requires `view_job_financials` hat)
- Export capability

### Job Reports (`JobReportsPage`)

- Summary reports for the job lifecycle
- Hours vs estimate comparison
- Budget vs actual comparison
- Stage completion timeline
- Worker assignment history

## 10. Questionnaire (`IOSQuestionnairePage`)

- GPS geofence triggers questionnaire when leaving job site
- Questions are stage-aware (different questions for different stages)
- Grouped by category
- "?" option for unknowns (logged for follow-up)
- Required before clock-out can complete
- Company-configurable questions (Settings → Clock-Out Questions)

## 11. Implementation Notes

### Service Layer Requirements

All job operations go through `JobsService` in WiredPartCore. No raw SQL in UI files.

Key service methods needed:
- `fetchJobs(filter:)` — with status filter support
- `fetchJobDetail(id:)` — full job with stats
- `updateJobStatus(id:, status:, reason:)` — with hat validation
- `fetchJobTodos(jobId:)` — with stage grouping
- `completeTodo(id:)` — with warranty classification
- `generateAISummary(jobId:)` — calls Foundation Models
- `fetchJobActivity(jobId:, date:)` — today's activity

### Hat Permissions for Jobs

| Hat | What It Controls |
|-----|-----------------|
| `manage_job_status` | Change job status |
| `manage_payment_holds` | Put/remove payment holds |
| `view_job_financials` | See budget, costs, profit |
| `manage_job_warranty` | Adjust warranty periods |
| `classify_warranty_work` | Confirm warranty vs new work |
| `edit_job_todos` | Add/edit/delete to-dos |
| `create_jpo` | Create job purchase orders |
