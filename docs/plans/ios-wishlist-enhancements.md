## Design Decisions (from issue #93)

### 3-Section Layout

| Section | source_type | Description |
|---------|------------|-------------|
| User Added | `"manual"` | Manually created by any user |
| Forecast Demand | `"forecast"` | Auto-generated by forecasting engine |
| System Auto-Added | `"system"` | Triggered by below-MIN logic on trucks/shop |

### Approval Flows

**User Added (`"manual"`):**
- Status: `pending` → auto-approves after **14 days** if no manager action
- `auto_approve_at` = created_at + 14 days
- `processAutoApprovals()` runs on page load to apply any overdue auto-approvals
- Manager can approve early or dismiss with reason

**Forecast Demand (`"forecast"`):**
- **≥ 80% certainty** (`certainty_score >= 0.80`): auto-approved when created
- **< 80% certainty**: remains pending, shows "Review needed — verify stock manually" badge
- Physical audit instruction means: manager should walk to shelf and count before approving/dismissing

**System Auto-Added (`"system"`):**
- Same rules as forecast (certainty drives auto-approve)
- Created when: truck/trailer stock < MIN AND shop does NOT have the part
- (If shop HAS the part → a movement is staged instead)

### Dismiss Requires Reason

- All dismissals (any section) require a text reason
- Minimum 10 characters
- Stored in `dismiss_reason` column
- Reason visible in item history (notes section)

### Missing DB Columns (migration 057b)

```sql
ALTER TABLE wishlist_items ADD COLUMN dismiss_reason TEXT;
ALTER TABLE wishlist_items ADD COLUMN auto_approve_at DATETIME;
ALTER TABLE wishlist_items ADD COLUMN certainty_score REAL;
```
